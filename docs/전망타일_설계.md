# 설계서 — 「매크로 및 금리 전망」 타일 (viewpoint)

소개 페이지 6개 타일 중 좌상단 타일의 설계다. 구현 시안이 `frontend/js/viewpoint.js`에 있다.

## 1. 구성

| 순서 | 항목 | 형태 |
|---|---|---|
| 1 | 한미 국채 투자의견 | **숫자를 그림(표)으로 시각화** |
| 2 | 미국 | 핵심 코멘트 2~3줄 |
| 3 | 한국 | 핵심 코멘트 2~3줄 |

## 2. 투자의견 숫자 체계

투자의견은 **정수 -2 ~ +2**로 입력한다. 0을 중립으로 두면 부호가 방향(축소/확대)을 뜻하고, 표에서의 위치는 `값 + 2`(0~4번째 칸)로 바로 계산된다.

| 숫자 | 한국어 | English | 칸 | 색 |
|---|---|---|---|---|
| -2 | 적극축소 | Strong underweight | 1 | 빨강, 진한 채움 |
| -1 | 축소 | Underweight | 2 | 빨강, 연한 채움 |
| 0 | 중립 | Neutral | 3 | 회색 |
| +1 | 확대 | Overweight | 4 | 청록, 연한 채움 |
| +2 | 적극확대 | Strong overweight | 5 | 청록, 진한 채움 |

## 3. 그림 규칙

```
          축소      중립     확대          ← 머리글: 축소(1~2칸) · 중립(3칸) · 확대(4~5칸)
미국   [ ][■][●][ ][ ]                    ← ■ 현재 전망, ● 직전 전망
한국   [ ][■][ ][ ][ ]
주: 9/17 기준. ●는 직전 전망               ← 날짜는 보고서 링크(주소가 있을 때). 시장별 날짜가 다르면 아래 각주 규칙 참고
```

- **현재 전망**: 해당 칸에 색 채움과 같은 색 테두리. 적극(±2)은 채움이 더 진하다. 색을 구분하기 어려운 경우를 위해 화면에 안 보이는 글자("현재 전망: 축소")도 함께 넣는다.
- **직전 전망**: 회색 원. **직전과 같으면 원을 그리지 않는다.** (첨부 그림의 한국 행이 이렇게 보여서 그렇게 해석함. 다르게 하려면 알려 준다)
- **각주**: 미국과 한국은 **각자의 기준일**을 가진다.
  - 두 시장의 날짜(와 링크)가 같으면 하나로 적는다: `주: 9/17 기준. ●는 직전 전망`
  - 다르면 시장 이름을 붙여 나눠 적는다: `주: 미국 9/17 · 한국 5/28 기준. ●는 직전 전망`
  - **직전 전망의 날짜는 적지 않는다.** 현재 기준일이 있으면 직전 전망은 "그 이전의 전망"이라는 뜻이 이미 담긴다.
  - 회색 원이 하나도 없으면 `●는 직전 전망` 부분을 생략한다.
  - 기준일이 없어도 회색 원이 있으면 `주: ●는 직전 전망`만 표시하고(원의 뜻을 알려 줘야 하므로), 둘 다 없으면 각주를 생략한다.
  - 날짜는 English에서 "Sep 17"로 바뀐다.
- **다크모드**: 같은 의미의 색을 어두운 배경용 색으로 바꿔 적용한다 (`style.css`의 `--neg`, `--pos` 등).
- **잘못된 값**(-2~+2 정수가 아님)은 그 행을 그리지 않고 건너뛴다.

## 4. 데이터 계약 (JSON)

화면이 받는 모양이다. 지금은 `frontend/data/viewpoint.json` 파일이 이 역할을 하고, 나중에 API(`GET /viewpoint`)가 같은 모양을 돌려주게 한다. 화면 코드는 주소만 바꾸면 된다.

```json
{
  "opinions": {
    "rows": [
      { "market": "US", "opinion": -1, "asOf": "2026-09-17", "asOfUrl": "", "prevOpinion": 0 },
      { "market": "KR", "opinion": -1, "asOf": "2026-05-28", "asOfUrl": "" }
    ]
  },
  "comments": [
    { "topic": "us", "ko": "…", "en": "…" },
    { "topic": "kr", "ko": "…", "en": "…" }
  ]
}
```

**시장마다 자기 투자의견과 기준일을 가진다.** 미국과 한국이 서로 다른 날짜에 의견을 바꿔도 된다.

| 필드 | 값 |
|---|---|
| `market` | `US`(미국), `KR`(한국) — 표의 행 순서는 US → KR 고정 |
| `opinion` | 현재 투자의견, -2 ~ +2 정수 |
| `prevOpinion` | 직전 투자의견, -2 ~ +2 정수 (없으면 생략. 현재와 같으면 원을 그리지 않음) |
| `asOf` | 그 시장의 현재 기준일 (`YYYY-MM-DD`). 없어도 그려진다 |
| `asOfUrl` | 기준일에 걸 링크 (선택) |
| `topic` | `us`(미국) · `kr`(한국) — 화면 순서는 미국 → 한국 고정 |
| `en` | 없으면 화면이 `ko`로 대신 표시한다 |

## 5. 입력용 CSV

`database/seed/`에 입력용 CSV가 있다. `viewpoint_opinions.csv`에는 현재 값이 채워져 있고, `viewpoint_comments.csv`는 열 제목만 있는 빈 양식이다. 엑셀에서 **"CSV UTF-8(쉼표로 분리)"** 로 저장한다.

**`viewpoint_opinions.csv`** — **시장마다 자기 기준일**에 한 행씩. 한 시장만 바뀌면 그 시장의 행만 추가한다.

| 열 | 예 | 설명 |
|---|---|---|
| `market` | `US` | `US`(미국) 또는 `KR`(한국) |
| `as_of` | `2026-09-17` | 그 시장의 기준일 (YYYY-MM-DD) |
| `opinion` | `-1` | -2 ~ +2 |
| `report_url` | `https://…` | 날짜에 걸 링크 (선택) |

작성 예 (미국과 한국의 기준일이 다른 경우):

```csv
market,as_of,opinion,report_url
US,2026-08-10,0,
KR,2026-08-03,-1,
US,2026-09-17,-1,
KR,2026-09-10,-1,
```

위 예에서 화면은 미국은 9/17 기준 -1(직전 0), 한국은 9/10 기준 -1(직전 -1)을 쓴다. 한국은 직전과 같은 -1이므로 회색 원이 생기지 않는다. **직전 행의 날짜는 화면에 나오지 않고**, 어느 행이 직전인지(시간순으로 바로 앞 행)를 가리는 데만 쓰인다.

**`viewpoint_comments.csv`** — 시장마다 기준일별로 한 행

| 열 | 예 | 설명 |
|---|---|---|
| `as_of` | `2026-09-17` | 기준일 |
| `topic` | `us` | `us`(미국) 또는 `kr`(한국) |
| `text_ko` | `…` | 한국어 코멘트 (2~3줄, 아래 길이 규칙) |
| `text_en` | `…` | English (선택) |

이력은 **덮어쓰지 않고 행을 추가**한다. 화면은 **시장별로** 가장 최근 기준일을 "현재", 그 시장의 바로 앞 기준일을 "직전"으로 자동 계산한다. 같은 표가 「투자 전략 히스토리」 타일의 원본도 된다. (코멘트도 미국·한국이 각자의 기준일을 가진다.)

## 6. 코멘트 작성 규칙

- 미국·한국 각각 **2~3줄**. 한국어로 **100자 이내**(DB 한도 200자)를 권장한다.
- 앞에 붙는 "미국", "한국" 이름표는 화면이 자동으로 붙이므로 본문에 쓰지 않는다.
- English를 비워 두면 한국어가 대신 표시된다.

## 7. 화면 배치

표는 위에 고정하고, 그 아래에 코멘트 두 항목이 남는 높이를 쓴다. 넘치면 코멘트 영역 안에서만 스크롤한다. 측정값(미국 103자·3줄, 한국 72자·2줄 기준):

| 화면 | 타일 폭 | 코멘트 영역 높이 | 필요한 높이 | 결과 |
|---|---|---|---|---|
| 1920×1080 | 613px | 267px | 약 90px | 여유 있게 전부 표시 |
| 1536×730 (FHD 노트북, 배율 125%) | 485px | 110px | 108px | 전부 표시 (여유 거의 없음) |
| 1366×768 | 429px | 127px | 127px | 전부 표시 (여유 없음) |

노트북에서는 여유가 거의 없으므로 코멘트는 미국 3줄·한국 2~3줄을 넘기지 않는 것이 좋다. 넘치면 스크롤이 생긴다.

## 8. 파일

| 파일 | 역할 |
|---|---|
| `frontend/js/viewpoint.js` | 표·각주·코멘트를 그린다. 언어를 바꾸면 다시 그린다 |
| `frontend/data/viewpoint.json` | 임시 표본 데이터 (나중에 API로 교체) |
| `frontend/css/style.css` | `.opinion`, `.comments` 등 스타일과 색 토큰 |
| `frontend/js/i18n.js` | `viewpoint.*`, `view.*`, `market.*` 문구 (한국어/English) |
| `database/seed/viewpoint_*.csv` | 입력용 CSV (`opinions`는 값 채워짐, `comments`는 빈 양식) |
| `database/schema.sql` | `treasury_opinions`, `viewpoint_comments` 테이블 초안 (아직 적용 안 함) |
